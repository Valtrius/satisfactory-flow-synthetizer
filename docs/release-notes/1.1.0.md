# Release highlights

- Satisfactory Flow Synthetizer now runs [in the browser](https://valtrius.github.io/satisfactory-flow-synthetizer/) as well as on the Windows desktop. All three exact result scopes run locally with selectable compute workers, cancellation and browser-local history. No solver backend or account is required.
- The browser version downloads and verifies its complete runtime on the first visit, then works offline from the local cache. Updates install beside the active version and wait for open app tabs to close, preserving running work and IndexedDB history.
- Selected layouts can be shared through self-contained links. The link includes the selected solution, needs no storage service and is independently verified before it is displayed. Desktop shares open in the public browser viewer by default.
- The redesigned workspace places collapsible Inputs, History and Layouts panels beside a larger topology graph. A consolidated graph toolbar covers rotation, SVG export, sharing, fullscreen, undo, redo and layout reset; the number-row `1`, `2` and `3` keys toggle the workspace panels.
- Search telemetry now reports the active proof stage, partition and worker progress, and the smallest operator-belt count found before optimality is proved. The desktop app also restores its window size, position and maximized state across launches.

![Satisfactory Flow Synthetizer 1.1.0 workspace](https://github.com/Valtrius/satisfactory-flow-synthetizer/raw/1.1.0/docs/usage.png)

The browser version currently takes longer to solve the same workloads than the desktop app. In the recorded two-repeat comparison, completed longer browser workloads took 1.85–3.01 times as long as the current native build. Completed results matched, while capped browser runs retained their validated layouts and correctly remained marked as incomplete. See the [native and browser benchmark](https://github.com/Valtrius/satisfactory-flow-synthetizer/blob/1.1.0/benchmarks/platform/results-20260912.md) for the measurements and limits.

The Windows build is unsigned, so Windows SmartScreen may warn on first run.
