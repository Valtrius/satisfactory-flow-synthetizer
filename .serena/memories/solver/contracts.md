# Solver and application contracts

Code map: solver-core has normalization (problem.rs), sound arithmetic bounds (lower_bound.rs), exact profiles (profile.rs), QF_LRA encoding (encoding.rs), Boolean counts (cardinality.rs), portable objective/root planning (planner/), and the incremental leaf protocol (leaf.rs). The default native-runtime feature adds process.rs, native.rs, native_api.rs, diagnostics.rs and the independent portfolio.rs host. solver-api defines exact contracts; solver-validation independently checks graph equations, capacity, reachability, global/SCC uniqueness and layout-v1 identity. solver-reference is the exhaustive small-case oracle. synthetizer-app/src/jobs separates snapshots from terminal/interruption projection; presentation separates rates, graph/feedback construction and outcome assembly. src-tauri/src/history separates its SQLite facade, schema/migrations, reads, writes and conversion. frontend owns queue and graph UI.

Scale rates/capacity by one positive factor while preserving terminals. Search N, exact L and all accounted profiles. Unary multiplicities, sorted same-type flows, direct single-input equalities and decreasing selected reachability paths preserve cycles and every physical graph. Unexpected extraction/validation failures stop the worker; reject nonunique steady states.

For multiple workers, every first-output producer is an exhaustive disjoint root; dispatch producers descending. Boolean All min N/L groups with >=2 outputs and >1 branch worker select from unsplit live roots. Fewer roots than branch workers: static second-output children replace parents and all must exhaust. Otherwise: parents continue, and a validated current-group optimum witness permits adaptive children in spare slots after unstarted parents. Stable rounds interleave second producers. Either the parent OR a complete child cover owns an obligation, never both. Partial/duplicate completions cannot prove exhaustion. Preserve the exact promoted scheduler from the qualified hybrid source.

Sparse/Boolean searches split the total workers independently; sparse gets the odd extra, one worker is Boolean only. Each branch owns its ledger. Join both branches and backend sessions before terminal events, return one proof owner, never sum ledgers. One min N/L stops siblings after the first proved optimum without claiming enumeration exhaustion. User cancellation wins over racing internal success and remains incomplete. Desktop cancellation closes when search seals; hidden shutdown owns and joins job threads before exit. See docs/development.md for persistence and cleanup dialogs.

History schema 4 stores no solver type. JSON versions through 2 and relational schema 3 migrate transactionally with selections and graph edits. Unknown/corrupt schemas fail without deleting data. Strip imported engine prefixes from layout caches. Five-second checkpoints preserve interrupted work as incomplete; terminal snapshots release after frontend acceptance. Detached acknowledged snapshots permit suffix appends only for unchanged prefixes. Corrections use full replacement; prefix mismatches recover atomically without rewriting unrelated entries. Keep history-fixtures/v2.sql and cross-language wire fixtures.

The collector establishes public layout keys after rate/terminal restoration; presentation reuses those keys, not private search keys. Terminal conversion reuses matching live best-known displays without proofs and reconstructs missing or finalized cache entries. Proof application and cancellation remain independent of display caching.

Portable host contract: execute LeafAction batches in one persistent session, publish an accepted witness before the next blocking call, and dispose the backend before PlannerEvent::Retired. An ExactPlanner owns one branch only. poll seals completion only after every dispatched leaf retires; cancellation accepted before that poll wins. Reject foreign job epochs in the host and stale group/leaf IDs in the planner. Raw branch events need the same caller-scale identity normalization as native SolutionCollector before app delivery. outcome normalizes and orders public identities. No unsafe Send/Sync bridges or private-heap atomics for cross-worker cancellation. Canonaut's vendored word-width patch and pre-port identity evidence are described in docs/web-backends.md and vendor/canonaut/PORTABILITY.md.

Browser host: solver-browser owns exact preparation, independent streaming planners, canonical identity and shared Rust presentation in solve.worker.ts. leaf.worker.ts owns one exact LeafDriver and cvc5 session per dispatched task, with independent heaps. browserJobs.ts owns attempts, admission, cancellation and the completion seal. browserComputePool.ts handles compute slots/receipts; browserCheckpoint.ts validates and durably appends accepted batches before acknowledging workers. Automatic uses every logical processor reported by navigator.hardwareConcurrency, with lower saved choices and no fixed eight-worker cap. Queue capacity scales with the worker budget while collection checkpoints remain at most 16 graphs. One complete branch owns proof; never sum independent ledgers. Terminate every active/idle worker before the host seals. Cancellation before sealing wins even during a received collection write; retain that batch then apply its Rust interruption_packet. Unknown, traps, posting failures and failed disposal cannot discharge proof. A failed disposal requires whole-worker termination. Startup has a 120-second limit per worker, not a solve deadline. Job get/watch keep metadata, one preferred graph and an immutable collection prefix, not the complete graph array. Stable source indices survive paging, sorting, selection and edits. IndexedDB schema 2 saves collection graphs/stats separately, rejects stale history revisions and preserves a bounded failed-write overlay for export/retry. Interrupted reloads remain incomplete and never resume. collectionPages.ts reuses summaries and sorted source indices for the latest viewed collection, loading only new suffixes; graph reads stay paged. Canonical keys and summary/sort indexes still grow with collection size. graphSelection.ts prepares reads/layouts while graphSession.ts owns the final selection/history commit. Failed preparation and same-row selection retain the displayed graph and undo history. resultPages.svelte.ts owns page requests; sharing/session.svelte.ts owns previews and explicit saves. Keep demand-driven execution and local content-hashed solver assets separate from the verifier; omit search assets in desktop mode. Production omits low-level verifier Wasm exports; build:web:verifier:qualification enables them separately. The service worker caches only manifest-listed same-origin build assets under a scope/build-specific cache, verifies byte counts and SHA-256 on network insertion, never calls skipWaiting/clients.claim, and never touches IndexedDB. Full offline readiness requires every runtime asset; source archives stay outside the runtime cache. Initial installation and candidate updates both cache the complete runtime. Before mounting, bootstrap reloads into the initial active worker and checks controlled document/build agreement. Failed initial installation allows online use; a successful later retry asks the user to finish work and reopen without taking over running work. Updates wait for all old app tabs to close.
